# CoursesApp

Android-приложение со списком курсов, авторизацией-заглушкой, избранным и локальным кэшем.

## Возможности

- экран входа с валидацией email/password;
- переходы на VK/OK;
- загрузка курсов из сети;
- отображение списка курсов;
- сортировка по дате добавления;
- добавление/удаление из избранного;
- экран избранных курсов;
- локальное хранение курсов и состояния избранного.

## Стек

- Kotlin
- XML Views
- ViewBinding
- Coroutines / Flow
- Retrofit / OkHttp
- Room
- Dagger 2
- Material Components
- RecyclerView + ListAdapter + DiffUtil
- Multi-module architecture

## Архитектура

Проект разделён на модули:

- `app` — точка входа, `MainActivity`, навигация, корневой Dagger component.
- `feature-login` — экран входа и валидация.
- `feature-main` — список курсов, избранное, ViewModel, use cases, repository.
- `core-network` — Retrofit, API, DTO.
- `core-database` — Room database, DAO, entities.
- `core-ui` — общие цвета, размеры, стили, шрифты, drawable-ресурсы.

В `feature-main` используется разделение на слои:

- `data` — реализация репозитория и мапперы.
- `domain` — модели, repository interface, use cases.
- `presentation` — Fragment, ViewModel, adapter, UI utils.

## DI

DI построен на Dagger 2.

- `AppComponent` находится в `app` и предоставляет зависимости из core-модулей.
- Feature-модуль получает зависимости через component dependencies.
- `MainComponent` создаётся внутри feature через `MainComponentViewModel`, чтобы компонент жил вместе с lifecycle фрагмента.
- `MainDepsStore` используется как точка передачи зависимостей из `app` в feature.

## Навигация

Навигация реализована вручную через `FragmentManager`.

`MainActivity` отвечает за контейнер экрана и bottom navigation, а логика открытия экранов вынесена в `AppNavigator`.

Login является стартовым экраном. После успешной валидации открывается главный экран и показывается нижнее меню.

## Работа с данными

Курсы загружаются через Retrofit из удалённого источника и синхронизируются с Room.

UI подписан на данные из базы через Flow. Это позволяет:

- показывать закэшированные данные без интернета;
- обновлять список после успешной загрузки из сети;
- хранить состояние избранного локально.

Если сеть недоступна, приложение продолжает показывать локальные данные.

## Асинхронность

Для фоновых операций используются Kotlin Coroutines и Flow.

- сетевой запрос выполняется в suspend-функциях;
- данные из Room наблюдаются через Flow;
- ViewModel обновляет UI через StateFlow;
- Fragment подписывается на состояние с учётом lifecycle.

## UI / UX

UI собран на XML по макету Figma.

- общие design tokens вынесены в `core-ui`;
- используются общие цвета, размеры, стили текста и drawable;
- карточки курсов используют локальные placeholder-изображения, так как API не содержит ссылок на изображения;
- bottom navigation и основные экраны приведены к единому стилю.

## Примечания

Минимальная версия SDK: 24.
API не предоставляет изображения курсов, поэтому для карточек используются локальные placeholder-изображения. Изображение выбирается стабильно по id курса, чтобы не меняться при сортировке списка.
